17 안드로이드 버전 지원 범위

같은 앱을 두 가지로 빌드해 두었습니다. 쓰시는 기기가 받아들이는 쪽을 설치하시면 됩니다. 패키지 이름이 같으므로 하나가 다른 하나를 대체합니다.

둘은 같은 소스에서 나오고 모두 API 36을 대상으로 하며, 플랫폼이 허락하는 한 똑같이 동작합니다. 굳이 나눈 이유는 안드로이드 4까지 내려가려면 몇 군데에서 옛 방식을 써야 하는데, 요즘 폰에까지 그 길을 걷게 할 이유가 없기 때문입니다.

17.1 구형 빌드가 다르게 동작하는 부분#

여섯 가지 작은 차이이며, 모두 별도의 코드가 아니라 기기 쪽 버전 검사 뒤에 놓여 있습니다.

그 밖의 것 — 서른네 가지 언어·문자 자판과 네 가지 별도 자판, 두벌식과 12키 조합기, 한자 변환, 플로팅 키보드, 물리 키보드, 자동 반복, 테마 — 은 둘 다 같은 코드입니다. java.time도, java.util.function도, 라이브러리 디슈가링도 쓰지 않기 때문에 구형 APK가 최신 APK보다 오히려 작습니다.

메모장과 유니코드 직접입력은 구형에서 어떻게 되나#

둘 다 온전히 동작합니다. 보통은 최신 플랫폼을 요구하는 종류의 기능이라, 구체적으로 적어 둡니다.

메모장(Memo) — 전부 됩니다. 정렬되는 열 머리글이 있는 목록, 각 행의 체크박스와 전체를 선택하는 머리글 체크박스, ▲▼ 순서 이동, 선택 삭제와 전체 삭제, 강제로 붙는 시각 줄과 그 옆의 제목, 키보드 자체 조합기로 메모 안에 한글을 쓰는 것, 그리고 편집 링크 둘째 줄(Cp Cut Paste Del Un Re)까지 버전 검사에 걸리는 부분이 하나도 없습니다. 두 가지는 짚어 둘 만합니다.

  • 되돌리기·다시하기는 메모장 자체 이력입니다. TextView에 들어 있는 되돌리기는 API 23이라 구형 빌드에서는 쓸 수 없습니다. 그래서 메모장이 자기 이력을 들고 있으며, 안드로이드 4.0에서도 똑같이 60단계까지 동작합니다.
  • 클립보드는 ClipboardManager.setPrimaryClip을 씁니다. API 11부터 있는 기능이라, 복사·잘라내기· 붙여넣기가 다른 앱과의 사이에서도 최신 폰과 똑같이 오갑니다.

다른 점은 눈에 보이지 않는 것 하나뿐입니다. 메모 입력칸은 시스템 키보드가 그 위에 뜨지 않도록 요청하는데(setShowSoftInputOnFocus, API 21), 그 아래 버전에서는 이 호출을 건너뜁니다. 건너뛰어도 문제가 없습니다. IME 창은 시스템 포커스를 쥐지 않아 애초에 키보드가 뜰 자리가 없기 때문입니다.

유니코드 직접입력(Uni) — 역시 온전히 동작합니다. 플로팅 패드, 최대 여섯 자리 16진수, OK로만 확정되고 Cancel이면 문서를 건드리지 않고 나오는 것, 물리 키보드에서의 동작까지 같습니다. U+FFFF보다 큰 코드도 서러게이트 쌍으로 정확히 입력됩니다. 다만 그 글자가 보이는지는 기기 글꼴의 몫이어서, 안드로이드 4.4 기기에는 대부분의 이모지와 후기 한자 확장 영역에 글리프가 없어 네모로 보입니다. 글자 자체는 올바르게 들어가 있으므로, 글꼴이 넉넉한 곳에 붙여넣으시면 제대로 나타납니다. 패드의 키 이름은 모두 ASCII라 어느 기기에서나 그려집니다.

한자 변환도 플로팅 후보 패널을 포함해 두 빌드가 같은 코드입니다.

아래 두 장은 구형 APK가 안드로이드 4.4.2 이미지에서 실제로 그려 낸 화면입니다. 링크 두 줄이 모두 있는 메모장과, 플로팅 창 안의 코드 포인트 패드입니다. 위에서 말씀드린 두 가지 한계도 그대로 보입니다. 패널 막대가 Menu < X Size라는 낱말로 나오고, U+2318 옆의 글자는 그 글꼴에 글리프가 없어 보이지 않습니다. 입력되는 코드 포인트 자체는 정확합니다.

안드로이드 4.0에서 멈추는 데에는 고집이 아니라 구조적인 이유가 있습니다. API 11 아래에는 InputMethodSubtype이 없어 한/영 모드를 만들 수 없고, KeyEvent.isCtrlPressed나 F키 코드가 없어 물리 키보드를 지원할 수 없으며, Insets.touchableRegion이 없어 플로팅 키보드를 만들 수 없습니다. API 9 아래에는 getSelectedText가 없어 선택 영역 한자 변환이 불가능하고 MotionEvent.getActionMasked도 없습니다. 안드로이드 2까지 내려가는 것은 이 키보드의 이식이 아니라, 훨씬 작은 다른 키보드를 만드는 일이 됩니다.

안드로이드 12(API 31) 이상에서는 두 빌드 모두 Material You 색을 씁니다. 그 아래에서는 둘 다 다듬어 둔 라이트/다크 색으로 돌아갑니다.

17.2 구형 빌드, 안드로이드 4.4에서#

킷캣 에뮬레이터에서 구형 APK를 실제로 돌려 찍은 화면입니다. 그림으로 그린 것도, 최신 빌드에 옛 이름표만 붙인 것도 아닙니다.

여기서 키 이름이 그림 기호 대신 낱말로 적혀 있는데, 이는 구형 빌드가 제 일을 하고 있다는 뜻입니다. 이전 시도의 화면에서는 메뉴 키가 빈칸으로 나왔습니다. 안드로이드 4.4에 ☰ 글꼴이 없기 때문입니다. 그 기호들을 믿을 수 있게 된 버전 아래에서는 아무것도 그리지 않는 대신 Menu, Copy, Bksp, Lang이라고 적습니다.

17.3 실제로 돌려 본 범위#

위 표는 실제로 실행해 확인한 버전들입니다. 나머지 구간은 구성으로 뒷받침됩니다. 앱이 호출하는 모든 플랫폼 API가 해당 빌드의 최저 버전에 존재하고, 그렇지 않은 것은 명시적인 버전 검사 뒤에 있습니다. 린트도 두 최저 버전 모두에서 오류 없이 통과합니다.
